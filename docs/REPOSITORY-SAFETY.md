# Защита репозитория от случайной публикации данных

Проверка локальная, без сетевых запросов, PowerShell 5.1 и Git. Новых зависимостей нет. Сканируются байты в индексе Git — именно будущий коммит, независимо от последующих правок рабочего файла. Значения находок и строки содержимого не выводятся: только путь и причина. При технической ошибке коммит тоже останавливается.

## Подключение после клонирования

```powershell
powershell.exe -NoProfile -File tools/Install-SafetyHook.ps1
```

Устанавливается только локальный `core.hooksPath = .githooks`. Глобальная конфигурация не меняется. Уже настроенные сторонние hooks автоматически не заменяются. Git не активирует hooks сам при клонировании — команду нужно выполнить для каждой новой копии проекта.

Ручной запуск:

```powershell
powershell.exe -NoProfile -File tools/Test-StagedSafety.ps1
powershell.exe -NoProfile -File tools/Test-StagedSafety.ps1 -AllTracked
```

Первый вариант проверяет добавленные/изменённые файлы индекса, второй — все отслеживаемые файлы индекса. Для английских сообщений — `-Language en`. Коды: 0 — проверка пройдена, 1 — найдены запрещённые данные, 2 — проверка не выполнена.

## Что блокируется

- Локальные данные `.local/`, корневые `output/`, `snapshots/`, `exports/`, `reports/`, `logs/`, `secrets/`, `credentials/`, включая принудительное добавление через Git.
- `.env`, `.env.*`, `*.env`, закрытые ключи, контейнеры сертификатов, дампы и журналы по расширениям. `.env.example` разрешён, но содержимое проверяется.
- Типичные токены GitHub/Slack/AWS, маркеры закрытых ключей, учётные данные в HTTP(S)-URL, похожие на секрет значения присваиваний и JSON-полей, конкретные пути профилей Windows.
- Снимки/модули/анализы/отчёты TunnelEye, распознанные по JSON-схеме, даже при переименовании файла; HTML-отчёты TunnelEye.
- Ссылки, вложенные репозитории, двоичные файлы и файлы больше 5 МБ требуют отдельного решения вместо автоматической публикации.

Синтетические полные снимки разрешены только в `tests/snapshots/*.json` с принятой тестовой формой snapshotId (`00000000-0000-4000-8000-…`). Наложения остаются тестовым форматом. Это маркер доверенного тестового материала, а не доказательство обезличивания: фикстуры по-прежнему нужно читать при ревью.

Для старых тестов DnsProxy/Connectivity разрешён ровно один известный выдуманный URL-префикс с тестовыми учётными данными. Другие значения в этих файлах проверяются. Явные тестовые имена профилей (`someone`, `PrivateUser`, `ExampleUser`, `TestUser`), системные профили и плейсхолдеры допускаются.

## Что делать при блокировке

Оставить реальные данные в `.local/`, убрать файл из индекса или заменить содержимое синтетическим. Для теста секрета собирайте выдуманное значение из частей во время теста, а не храните полный токен в исходнике. При ложном срабатывании сначала разберите причину; не расширяйте исключение на весь каталог тестов.

## Границы защиты

`.gitignore` не удаляет уже отслеживаемые файлы и прошлые коммиты. Hook проверяет индекс, не всю историю и не сообщения коммитов. Он не умеет распознавать любые персональные данные, неизвестные токены или гарантировать обезличивание фикстуры. Умышленно обходится, например, `git commit --no-verify`; это страховка от ошибки, а не серверный запрет. Проверка CI и аудит истории — отдельные задачи.

История и старые фикстуры этой правкой не меняются. Реальные секреты при обнаружении сначала отзываются/заменяются; очистка истории требует отдельного согласования.
