# Отчёт и экспорт — часть 2.3

`Report.Build(snapshot, analysis, language)` формирует независимую копию данных для CLI, HTML и будущего WPF. Язык — `ru` (по умолчанию) или `en`. Тексты правил берутся из JSON, подписи отчёта — из `.resx`.

## JSON `tunneleye.report/1`

- `snapshotId`, `createdAt` — идентификатор и время исходного снимка; `version` — версия анализатора.
- `language`, `masked` — язык и признак маскированного отчёта.
- `collection.elevated` — nullable-признак прав исходного сбора: `true` — с администратором, `false` — без него, `null` — старый снимок без отметки. В HTML/WPF/CLI режим показан постоянно; неизвестный режим не считается отсутствием прав. Поле добавлено совместимо в `tunneleye.report/1`; прежний `tunneleye.analysis/1` не меняется.
- `summary.score`: `red` — неэкспериментальная критическая находка; `yellow` — важная; `gray` — неполная критическая проверка, ошибка загрузки/вычисления либо пустой набор правил; иначе `green`. Красный и жёлтый имеют приоритет над серым.
- `summary.counts` — число находок по четырём уровням, включая экспериментальные; `incompleteCritical` — идентификаторы неполных критических проверок; `recommendations` — до трёх ID находок (сначала подтверждённые, затем экспериментальные; по важности).
- `checks[]`: `id`, `level`, `experimental`, `status`, локализованные `title`, `why`, `fix`, `details`; `reason`, `hint`, `limitations`; `evidenceCount` и `evidence[]` (`values`, `sources`).
- `status`: `found`, `notFound`, `notChecked`, `notApplicable`. Пропущенный модуль с причиной `NotSupported` — не применимо; ограничения критических правил учитываются даже при `notFound`.
- `sections` — технические данные модулей: сеть, службы, железо и система. Это копия собранных данных, не результат новой диагностики.
- `charts` — числовые серии `{ label, value }`: `Latency` (RTT, мс), `Losses` (ICMP, %), `DnsLatency` (мс), `WifiChannels` (канал и сигнал, %), `WifiUtilization` (загрузка канала, %), `EventTimeline` (имеющиеся отметки событий по дням UTC; выборка может быть усечена сборщиком). Пропущенное измерение не становится нулём. Подпись RTT включает интерфейс; ответ туннеля не равен ответу внешней цели.
- `modules[]` — имя, статус, ошибки. Причины `skipped` не включаются в ошибки модуля. `ruleErrors`, `evaluationErrors` — отдельные ошибки анализа.

## HTML

Один файл, без скриптов, сетевых ресурсов и внешних шрифтов. CSP по D-015. Все динамические значения проходят один хелпер HTML-кодирования, в том числе SVG-подписи. Графики — встроенный статический SVG; раскрытие — `<details>`. Доказательства hosts сгруппированы по адресу и свёрнуты. Схема сети показывает строки «адаптер → шлюз → префикс», не пытаясь восстановить топологию за пределами ПК.

Статический SVG сейчас формируется ядром без дополнительных пакетов. Интерактивное представление WPF и OxyPlot — часть 2.4. Технические данные модулей раскрываются как JSON; пользовательские вкладки и расширенное представление — 2.4. Захват и анализ трафика — этап 3; апгрейд — этап 5.

## Маскировка

`PrivacyMasker` создаётся для одного экспорта. Одна таблица псевдонимов используется в отчёте, HTML, анализе и экспортируемом снимке; исходные объекты не меняются. Таблица соответствий не экспортируется.

Маскируются IP (включая IPv6, префиксы и адреса внутри строк), MAC, имена ПК/пользователя, домен/рабочая группа, DNS-суффиксы, SSID/имена сетевых профилей, имена VPN-профилей и их серверов, прокси/PAC и имя пользователя в путях профиля. Найденные личные значения заменяются в строках экспорта, включая переменные окружения прокси, исключения прокси и NRPT (скалярный/массивный namespace и имена серверов nameServers). Замены выполняются за один проход, чтобы не менять уже созданные псевдонимы. Разные написания одного IPv6/MAC получают один псевдоним; адреса в ключах словарей тоже маскируются. Служебные идентификаторы формата и явные поля моделей/part number оборудования сохраняются. Модели и part number железа не являются личными полями и отдельно не маскируются (D-012).

## CLI

```powershell
dotnet build src/TunnelEye.sln
src/TunnelEye.Cli/bin/Debug/net48/tunneleye.exe analyze snapshot.json --lang ru --report-json report.json --html report.html --mask --snapshot-json snapshot-safe.json
```

`--json` сохраняет прежний `tunneleye.analysis/1` для совместимости; `--report-json` — новый отчёт. `--mask` применяется ко всем экспортам и выводу результатов. `--snapshot-json` без `--mask` сохраняет полные данные. Исходный снимок и выходные пути должны различаться; коллизии отклоняются. Ошибка записи возвращает код 3, неверные параметры — 2.

Отчёт из тестового наложения сначала разворачивается скриптом `tests/Expand-Overlay.ps1`; CLI принимает полноценный снимок.

## Объяснения конфигурации (D-017)

Необязательный корневой `explanations` — массив объектов. Старый отчёт без него отображается прежним способом. Существующие checks/status, summary и analysis/1 не заменяются. Объяснения строятся из контекста того же анализа; для вручную созданного AnalysisResult без контекста возвращается явная карточка недостаточности, а не повторный независимый анализ.

- `id`: служебный идентификатор, без личных значений; `ruleId`: string или null.
- `placement`: `configuration` или `finding`; `assessment`: `expectedBehavior`, `possibleCause`, `confirmedConfigurationProblem`, `insufficientData`.
- `title`, `mechanism`, `possibleSymptom`, `action`, `primaryLimitation`: локализованные строки первого экрана.
- `claims[]`: `id`, `kind` (`observed`, `derived`, `hypothesis`, `recommendation`), `availability` (`known`, `unknown`), `text` string, `scope` string (локализованная область с возможными личными значениями), `evidenceRefs` string[], `limitations` string[]. Строки с unknown не удаляют известные соседние утверждения.
- `evidence[]`: `id`, `kind` (`row`, `section`, `measurement`), `sources` string[] (канонические пути относительно модулей снимка, как у checks.evidence), `values` object с исходными значениями. Ссылка на полную секцию обосновывает отсутствие элемента; вымышленной строки нет.
- `path`: объект с `nodes[]` и `edges[]`. Узел: `id`, `text` string, `claimRefs` string[]. Связь: `id`, `from`, `to` (ID узлов), `kind` (`configured`, `locallySelected`, `measured`, `unknown`), `text` string, `claimRefs` string[]. Все ID/ссылки служебные; подписи маскируются. Неизвестный узел явно подписан. Measured относится только к конкретному тесту, а не автоматически к соединению приложения.
- `limitations`: string[] — локализованные границы вывода и данные о неполноте, без придуманных времён. Технические причины доступны в доказательствах; время снимка остаётся в createdAt. Секции не считаются одновременно собранными.

Enum и служебные ссылки защищаются от замены маскировкой только в этих строго определённых путях. `text`, `scope`, подписи узлов/связей, значения и ограничения всегда проходят маскировку. JSON/HTML строятся из одного маскированного дерева. Заголовок и существенное ограничение видны без раскрытия, доказательства и технический JSON — по раскрытию.

### Факт `tunnel-route-overlaps`

Добавочный факт каталога `facts/1`, прежние имена/поля сохранены. Только текущие широкие префиксы /0 и две канонические /1 отдельно для IPv4/IPv6. Запись на пару известных клиентов и семейство: `clientAId`, `clientBId`, `family`, `overlapConfirmed=true`, `overlapPrefixes` string[], `interfaceIndexesA/B` int[]. Источники включают маршруты, адаптеры, состояния интерфейсов и записи клиентов. Половина /1 не означает полного покрытия; противоположные /1 не пересекаются; метрики не доказывают причинность.

Неизвестный клиент, generic-компонент/драйвер, неоднозначные притязания на один адаптер или неполный инвентарь дают ограничения и не доказывают двух клиентов. Пустой результат с ограничениями не означает «конфликта нет». Положительные строки сохраняются при неполноте других секций.
