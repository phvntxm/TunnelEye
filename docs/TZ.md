# ТЗ: TunnelEye

> Рабочая копия ТЗ для разработки. Обсуждаемая версия живёт в Claude Docs; при расхождении — обновить этот файл.

## Назначение

**Название:** TunnelEye — продукт; Argus — имя ядра анализа (`Argus.Core` в коде), используется в логотипе и README.

Инструмент для Windows-ПК: по одной кнопке собирает полную картину сети и системы, по кнопке «старт/стоп» пишет трафик и выдаёт отчёт с найденными проблемами и конкретными шагами по исправлению.

**Пользователи:**

- **Обычный пользователь** — нажал кнопку, получил отчёт простым языком: что не так, насколько это важно, что сделать.
- **Продвинутый** (админ, сетевик, энтузиаст) — расширенный режим: выбор модулей, сырые данные, фильтры захвата, экспорт, сравнение снимков.

**Границы продукта (что НЕ делает):**

- Не меняет систему без явного подтверждения пользователя; любое изменение — с бэкапом и откатом.
- Не диагностирует сеть за пределами ПК (коммутаторы, роутер) — только то, что видно с самого ПК.
- Не обходит блокировки и не настраивает VPN — только находит конфликты и объясняет их.

**Платформа:** Windows 10 (1903+) и 11, x64. Требуются права администратора для полного сбора; без них — урезанный режим с пометкой в отчёте.

**Языки интерфейса:** русский и английский; локализация закладывается с первого этапа.

## Основной сценарий: один клик

От нажатия до отчёта пользователь делает два действия: «Начать» и, если нужен захват трафика, «Стоп».

1. **Запуск.** Пользователь жмёт «Диагностика». Инструмент запрашивает права администратора (UAC) и создаёт точку бэкапа сетевой конфигурации.
2. **Снимок системы** (1–3 мин). Последовательно отрабатывают все модули сбора, прогресс виден на экране.
3. **Захват трафика** (по желанию). «Старт захвата» → пользователь воспроизводит проблему → «Стоп». Лимит по умолчанию — 10 минут или 500 МБ.
4. **Анализ.** Правила детекта прогоняются по снимку и дампу.
5. **Отчёт.** Открывается в окне программы, с графиками: сводка, проблемы по приоритету, рекомендации, апгрейд железа.
6. **Исправление** (по желанию). У рекомендации с безопасным автофиксом — кнопка «Применить». Перед применением показывается, что изменится; после — кнопка «Откатить».

## Модули сбора

Каждый модуль — независимый блок с единым форматом вывода (JSON); падение одного модуля не останавливает остальные, а помечается в отчёте.

| Модуль | Что собирает | Источник |
| --- | --- | --- |
| Система | Версия и сборка Windows, uptime, последние обновления, профиль сети | `Get-CimInstance Win32_OperatingSystem`, `Get-HotFix`, `Get-NetConnectionProfile` |
| Адаптеры и драйверы | Все адаптеры, включая скрытые и виртуальные (TAP/TUN, Wintun, Hyper-V, WSL, VirtualBox, VMware); версия, дата и подпись драйвера; привязки протоколов; расширенные свойства (offload, energy saving, jumbo) | `Get-NetAdapter -IncludeHidden`, `Get-NetAdapterBinding`, `Get-NetAdapterAdvancedProperty`, `Get-PnpDevice`, `pnputil /enum-drivers` |
| Маршрутизация | Таблица маршрутов v4/v6, метрики, шлюзы, мосты, ICS | `Get-NetRoute`, `Get-NetIPInterface`, `Get-NetIPConfiguration` |
| DNS и прокси | DNS по интерфейсам, DoH, суффиксы, NRPT, кэш, системный и WinHTTP-прокси, PAC, hosts | `Get-DnsClientServerAddress`, `Get-DnsClientDohServerAddress`, `Get-DnsClientNrptPolicy`, `netsh winhttp show proxy`, реестр Internet Settings |
| Firewall и фильтры | Правила брандмауэра, фильтры и callout-драйверы WFP, провайдеры WFP | `Get-NetFirewallRule`, `netsh wfp show filters`, `netsh wfp show state` |
| VPN и туннели | Встроенные VPN-профили, клиенты, их службы и адаптеры, kill switch, split tunneling | `Get-VpnConnection`, службы и адаптеры по сигнатурам |
| Службы и автозагрузка | Сетевые службы, автозапуск, задачи планировщика, NDIS LWF | `Get-Service`, `Win32_Service`, `Get-ScheduledTask`, `Get-NetAdapterBinding` |
| Соединения | TCP/UDP-соединения и слушающие порты с привязкой к процессам | `Get-NetTCPConnection`, `Get-NetUDPEndpoint`, `Get-Process` |
| TCP-стек | Автонастройка окна, RSS, ECN, congestion provider | `netsh int tcp show global`, `Get-NetTCPSetting` |
| Тесты связи | Пинг шлюза и внешних узлов, трассировка, резолв через разные DNS, подбор MTU | `Test-NetConnection`, `tracert`, `Resolve-DnsName`, `ping -f -l` |
| Wi-Fi | Сигнал, канал, стандарт, скорость линка, драйвер | `netsh wlan show interfaces`, `netsh wlan show drivers` |
| Журналы | Ошибки адаптеров, DNS-клиента, разрывы линка за 7 дней | `Get-WinEvent` |
| Железо | CPU, GPU, RAM, диски (тип, SMART), материнка и BIOS, сетевая карта | `Win32_Processor`, `Win32_VideoController`, `Win32_PhysicalMemory`, `Get-PhysicalDisk`, `Win32_BaseBoard`, `Win32_BIOS` |

## Захват и анализ трафика

По умолчанию встроенный `pktmon`; если уже есть Npcap и Wireshark — можно переключиться на `dumpcap`.

**Захват:**

- `pktmon start --capture` → `pktmon stop` → `pktmon etl2pcap` (pcapng).
- `dumpcap` — альтернатива. Npcap инструмент не устанавливает и не распространяет.
- Лимиты: 10 минут, 500 МБ, кольцевой буфер; меняются в расширенном режиме.
- Раз в 5 секунд снимается таблица соединений с PID, чтобы связать трафик с процессами.
- Интерфейсы: по умолчанию все, включая VPN-адаптер.

**Что анализируется:**

- Топ процессов и направлений: кто и куда ходит в фоне, объём, частота.
- Broadcast/multicast, ARP-шторм, повторяющиеся кадры — признаки петли в локалке.
- Качество TCP: ретрансмиты, дубли ACK, нулевое окно, RST.
- DNS: запросы мимо туннеля (утечка), таймауты, NXDOMAIN, подмена ответов, DoH.
- MTU: ICMP «fragmentation needed», зависшие TLS-рукопожатия.
- Трафик в обход туннеля при включённом VPN.
- Подозрительное: нестандартные порты, неизвестные процессы, телеметрия.

**Обработка:** собственный парсер нужных протоколов (Ethernet, ARP, IPv4/IPv6, TCP, UDP, DNS, ICMP); в отчёт попадают агрегаты, а не сырые пакеты.

## Правила детекта

Каждое правило — отдельный JSON-файл: условие, уровень, текст для новичка, техническое описание, рекомендация. Новые правила добавляются без правки ядра.

Уровни: **Критично**, **Важно**, **Совет**, **Инфо**.

| Проблема | Как детектится | Уровень |
| --- | --- | --- |
| Петля маршрутизации | Маршрут через интерфейс, который маршрутизирует обратно; TTL exceeded в трассировке | Критично |
| Петля / шторм в локалке | Broadcast > 10%, ARP > 100/с, повторяющиеся кадры | Критично |
| Мост между адаптерами | MAC Bridge или ICS между физическим и виртуальным адаптером | Важно |
| Два шлюза по умолчанию | Несколько default route с близкими метриками | Важно |
| Конфликт VPN | Несколько активных туннелей; пересекающиеся маршруты; WFP-фильтры разных VPN | Критично |
| DNS-утечка | При VPN DNS уходит через физический адаптер; DNS провайдера в списке | Важно |
| Конфликт VPN и блокировок / антивируса | WFP-фильтры разных провайдеров на одних слоях с противоречащими действиями | Важно |
| Мёртвый прокси | Прокси указывает на недоступный адрес | Критично |
| Подмена в hosts | Записи для банков и платёжных сервисов; адреса, не принадлежащие сервису | Важно |
| Обход блокировок в hosts | Захардкоженные IP популярных сервисов (мессенджеры, соцсети, CDN) — адреса устаревают | Совет |
| Устаревший драйвер | Старше 3 лет; generic-драйвер Microsoft вместо драйвера производителя | Совет |
| Энергосбережение на адаптере | Green Ethernet / EEE на десктопе | Совет |
| Проблемы MTU | MTU < 1500 без туннеля; «fragmentation needed» | Важно |
| Плохое TCP-качество | Ретрансмиты > 2% | Важно |
| Лишние службы | Службы и адаптеры от удалённого ПО; остатки старых VPN | Совет |
| Слабый Wi-Fi | Сигнал < 50%, загруженный канал 2,4 ГГц, линк ниже возможностей | Совет |
| Открытые порты | Слушающие порты на 0.0.0.0 в публичном профиле | Важно |

Пороги — стартовые, уточняются на тестах и настраиваются в расширенном режиме.

## Апгрейд железа

2–3 варианта апгрейда под разный бюджет с объяснением, что каждый даст.

- **Узкие места:** мало RAM, одноканальная память, HDD как системный, слабый CPU, сетевая карта 100 Мбит при гигабите, Wi-Fi 4/5 при роутере Wi-Fi 6.
- **Совместимость:** сокет, чипсет, тип и максимум памяти, слоты M.2/SATA/PCIe, БП (если пользователь укажет), версия BIOS для CPU.
- **Варианты:** «Минимум», «Оптимум», «Максимум без замены платформы»; отдельно — когда честнее менять платформу.
- **Модели вместо цен:** кнопки «Искать в DNS», «Ozon», «Яндекс Маркет» открывают поиск по модели в браузере. Цены инструмент не собирает.
- **Сценарий:** игры, работа, сервер, офис — от этого зависят приоритеты.

Парсинг магазинов отклонён: антибот-защита и правила площадок. База моделей обновляется вместе с версиями инструмента.

## Расширенный режим

Переключатель «Для продвинутых»; основной сценарий не меняется.

- Выбор модулей и правил по отдельности.
- Фильтры захвата: интерфейс, протокол, порт, IP, процесс; BPF для `dumpcap`.
- Настройка лимитов захвата и порогов правил.
- Сырые данные: JSON модулей, pcapng, логи.
- **Сравнение снимков** «до/после».
- **Мониторинг по расписанию** с уведомлением об изменениях.
- CLI с теми же функциями.
- Ручное управление исправлениями: просмотр команды, применение по одной, журнал.

## Формат отчёта

Окно программы с графиками и раскрывающимися деталями; экспорт в самодостаточный HTML (офлайн) и JSON.

1. **Сводка:** оценка (зелёный / жёлтый / красный), число проблем по уровням, три главные рекомендации.
2. **Проблемы** по важности: заголовок простыми словами, «почему это плохо», технические детали по клику, что сделать, кнопка «Применить» при безопасном автофиксе.
3. **Сеть:** схема адаптеров и маршрутов, DNS, VPN, прокси.
4. **Трафик:** топ процессов и направлений, качество соединений, аномалии.
5. **Службы и автозагрузка:** что лишнее и почему.
6. **Железо и апгрейд.**
7. **Приложение:** версия, дата, какие модули отработали или упали.

Кнопка «Экспорт без личных данных» — IP, MAC, имена ПК и пользователя, DNS-суффиксы, имена Wi-Fi-сетей (SSID), имена VPN-профилей и адреса VPN-серверов замаскированы.

## Безопасность и приватность

Всё работает локально; без явного согласия наружу не уходит ни байта.

- Дамп хранится только локально, удаляется кнопкой или автоматически через 7 дней.
- Единственная онлайн-функция — проверка обновлений, по умолчанию выключена. Кнопки поиска в магазинах только открывают браузер.
- В отчёт и экспорт не попадают пароли, ключи Wi-Fi, содержимое пакетов, история браузера.
- Изменения системы: бэкап, подтверждение, журнал, откат. Опасные действия — только в расширенном режиме, с предупреждением.
- Скрипты подписаны; не требуется отключать антивирус или Execution Policy глобально.
- Код открыт.

## Архитектура и стек

Оркестратор запускает независимые модули, складывает всё в локальный снимок, анализатор прогоняет правила и собирает отчёт; исправления — отдельный компонент с бэкапом и откатом.

```
Интерфейс (WPF + CLI)
        │
   Оркестратор ──────────────┬───────────────┐
        │                    │               │
 Модули сбора (PS)   Захват (pktmon)   Исправления (бэкап/откат)
        └────────┬───────────┘
          Снимок (JSON + pcapng)
                 │
        Анализатор Argus (правила, C#)
                 │
   Отчёт (в окне + экспорт HTML/JSON)
```

| Слой | Технология | Почему |
| --- | --- | --- |
| Модули сбора | PowerShell 5.1 | Есть в каждой Windows 10/11 |
| Захват | `pktmon`, `dumpcap` (если есть) | Без установки драйверов |
| Ядро, анализатор, GUI | C#, .NET Framework 4.8, WPF | Встроен в Windows 10 1903+ и 11; exe — единицы МБ |
| Графики | OxyPlot (MIT) | Лёгкая, работает с WPF на .NET Framework |
| Разбор pcapng | Собственный парсер | Ограниченный набор протоколов |
| Правила | JSON-файлы | Правятся без изменения кода |
| Локализация | .resx, RU и EN | Стандартный механизм WPF |

**Целевой размер:** дистрибутив ≤ 20 МБ.

Риск релиза: неподписанный exe с правами админа блокируют SmartScreen и антивирусы — подпись кода обязательна для публичной версии.

## Этапы и критерии приёмки

| Этап | Результат | Критерий приёмки |
| --- | --- | --- |
| 1. Сбор | Все модули, единый JSON-снимок | Снимок на Windows 10 и 11 за ≤ 3 мин; падение модуля не ломает остальные; без админа — урезанный снимок с пометкой |
| 2. Анализ и интерфейс | Правила (без трафика), окно с отчётом и графиками, экспорт HTML/JSON | На стенде находятся все заложенные проблемы (два шлюза, мёртвый прокси, DNS-утечка, лишний TAP, подмена в hosts); HTML открывается офлайн |
| 3. Трафик | Захват старт/стоп, анализ дампа | Остановка по кнопке и лимитам; находит ARP-шторм и ретрансмиты на стенде; трафик привязан к процессам |
| 4. Исправления | Автофиксы с бэкапом и откатом | Каждое исправление откатывается в исходное состояние (снимок до/после) |
| 5. Железо | Узкие места, варианты, кнопки поиска | Совместимость верна на 3 конфигурациях; кнопки открывают поиск по точной модели |
| 6. Расширенный режим и релиз | Расширенный режим, CLI, EN-локализация, подписанный exe | Запуск на чистой Windows 10 и 11 без зависимостей; ≤ 20 МБ; Defender не блокирует; интерфейс на двух языках |

**Регресс:** на каждом этапе — набор тестовых снимков с известными проблемами; правило рабочее, если находит свою проблему и не даёт ложных срабатываний на «чистом» снимке.

**Тестовый стенд:** ВМ Windows 10 и 11 с намеренно сломанной конфигурацией (два VPN-клиента, мост, мёртвый прокси, кривые маршруты) + ПК автора как реальный кейс.
