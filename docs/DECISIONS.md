# Журнал решений

Решения, которые меняют архитектуру или уточняют ТЗ. Новые — снизу.

## D-001. Единая схема снимка v1 — 2026-10-23

Каждый модуль сбора выдаёт конверт `tunneleye.module/1` (`schema`, `module`, `version`, `status`, `elevated`, `startedAt`, `durationMs`, `errors`, `data`); оркестратор собирает `snapshot.json` (`tunneleye.snapshot/1`) и кладёт рядом конверты модулей. Статусы: `ok`, `partial`, `failed`, `skipped`. Ошибки привязаны к источнику и классифицированы (`AccessDenied`, `NotSupported`, `NotFound`, `Timeout`, `Exception`).

Подробно: [schema/README.md](schema/README.md).

## D-002. Тесты связи: наружу только по явному согласию — 2026-10-23

Противоречие: ТЗ требует пинг внешних узлов, трассировку и резолв через разные DNS; CLAUDE.md запрещает сетевые запросы наружу.

Решение: модуль `connectivity` по умолчанию проверяет только локальное — шлюз, настроенные DNS-серверы, MTU до шлюза. Внешние узлы — только по явному флагу (CLI) или согласию пользователя (GUI); список адресов — в конфиге, не в коде.

## D-003. DNS-кэш: только агрегаты и подозрительное — 2026-10-23

DNS-кэш по сути — история посещений, которую ТЗ запрещает выносить в отчёт.

Решение: в снимок попадают число записей, доля ошибок и только записи, совпадающие с hosts или подозрительными адресами. Полный кэш — только в расширенном режиме.

Уточнение при реализации (2026-10-23, принято владельцем): Windows загружает весь hosts в DNS-кэш, поэтому совпадения с hosts хранятся только счётчиком (`fromHosts`) — сами записи уже есть в секции `hosts`. Списком хранятся ответы с адресом-«чёрной дырой» (`0.0.0.0`, `127.x`, `::`) для имён не из hosts, не более 200.

## D-004. Каждый модуль — отдельный процесс — 2026-10-23

Оркестратор запускает каждый модуль в своём `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass` с таймаутом (по умолчанию 120 с); по таймауту убивается всё дерево процессов. Зависший, упавший или выдавший мусор модуль превращается в конверт `failed`, остальные не затрагиваются. Цена — около 0,5 с на запуск модуля.

`-ExecutionPolicy Bypass` действует только на дочерний процесс; политика машины не меняется (ТЗ: «не требуется отключать Execution Policy глобально»).

## D-005. Технические соглашения сбора — 2026-10-23

- JSON пишется через `System.Web.Script.Serialization.JavaScriptSerializer` (есть в .NET Framework 4.8), а не `ConvertTo-Json`: тот в PS 5.1 пишет enum числами, молча обрезает вложенность и разворачивает массивы из одного элемента. Перед сериализацией данные нормализуются (`ConvertTo-CollectorData`).
- Файлы — UTF-8 без BOM.
- Исходники `.ps1`/`.psm1` — только ASCII: PowerShell 5.1 читает файлы без BOM как ANSI. Проверяется тестом.
- Вывод консольных утилит декодируется с автоопределением: BOM → UTF-16 → строгий UTF-8 → лучшая по оценке из OEM и ANSI (буквы против псевдографики и символов). Утилиты пишут по-разному: `netsh` — в кодовой странице унаследованной консоли (866 или 65001), `pnputil` при перенаправлении — в ANSI 1251. Язык вывода тоже зависит от окружения запуска, поэтому парсеры не опираются на метки.
- Приоритет источников: командлеты → CIM → реестр → `netsh` (локализован; разбор + исходный текст в `raw`).
- Тесты — встроенный Pester 3.4, ничего не устанавливается.

## D-006. Маскировка DNS-суффиксов и SSID при экспорте — 2026-10-23

DNS-суффиксы (модуль `dns-proxy`) часто содержат корпоративные домены, имя Wi-Fi-сети (`system.networkProfiles[].name`, модуль `wifi`) указывает на место. Решение: «Экспорт без личных данных» маскирует их наравне с IP, MAC, именами ПК и пользователя. ТЗ обновлено (раздел «Формат отчёта»). Сбор не меняется: данные нужны анализатору, маскировка — при экспорте.

## D-007. Уточнения правил этапа 2 по итогам приёмки `dns-proxy` — 2026-10-23

1. **IPv6 DNS `fec0:0:0:ffff::1`–`::3`** — значения Windows по умолчанию для интерфейсов без настроенного DNS (устаревшие site-local). Правила («DNS провайдера», «DNS-утечка» и другие) их игнорируют: это не настроенный сервер.
2. **Правило hosts различает обход блокировок и подмену.**
   - Обход блокировок: захардкоженные IP популярных сервисов (мессенджеры, соцсети, CDN) — уровень «Совет», текст «проверь актуальность»: адреса устаревают, и сервис перестаёт открываться.
   - Подмена: банки и платёжные сервисы, адреса, не принадлежащие сервису, другие неожиданные адреса — уровень «Важно».
   Конкретные списки доменов и диапазонов — в JSON правила, не в коде. ТЗ обновлено с согласия владельца: строка «Подмена в hosts» разделена на «Подмена в hosts» («Важно») и «Обход блокировок в hosts» («Совет»).
3. **Пара фикстур «прокси / TUN» для теста DNS-утечки.** Нужны снимки `dns-proxy` и `routing` с VPN-клиентом в режиме системного прокси и в режиме TUN; из них делается обезличенная пара фикстур, реальные снимки не коммитятся.
   Уточнение (2026-10-23, владелец): снимаются не на машине разработки, а позже на виртуалке тестового стенда. На машине разработки Happ работает без системного прокси и без TUN, так что такой пары там не получить.

## D-008. Маскировка имён VPN-профилей и адресов VPN-серверов при экспорте — 2026-10-23

Имена встроенных VPN-профилей и адреса VPN-серверов (модуль `vpn`: `builtIn.profiles[].name`, `serverAddress`, `servers[]`) часто указывают на организацию. Решение: «Экспорт без личных данных» маскирует их наравне с данными из D-006. ТЗ обновлено (раздел «Формат отчёта»). Сбор не меняется: данные нужны анализатору, маскировка — при экспорте.

## D-009. Соединения: публичные удалённые адреса — только счётчиками — 2026-10-24

Список установленных соединений с публичными удалёнными адресами показывает, куда ходит пользователь, — по сути история посещений, которую ТЗ запрещает выносить в отчёт (как DNS-кэш в D-003).

Решение (принято владельцем, вариант A):
- Слушающие TCP-порты и UDP-точки — полностью (адрес, порт, процесс).
- Соединения TCP: локальная сторона (адрес, порт), процесс, состояние и удалённый порт — всегда. Удалённый адрес — полностью, только если он не публичный: loopback, частные сети, CGNAT (`100.64.0.0/10`), link-local, unique local, multicast, неуказанный (`0.0.0.0`, `::`).
- Соединения с публичным удалённым адресом сводятся в счётчики по ключу «процесс + локальный адрес + удалённый порт»: число соединений, разбивка по состояниям и **число уникальных публичных адресов**. Сами публичные адреса не хранятся.
- Полный список с публичными адресами — только в расширенном режиме.

Для правила «трафик мимо туннеля» (этап 2): соединения процессов VPN-клиентов и ядер прокси (`xray`, `sing-box`, `wireguard`, `openvpn` и т. п. — по `vpn.clients`, в том числе `owners`) через физический интерфейс — это сам туннель до VPN-сервера, а не утечка. Утечка — соединения остальных процессов через физический интерфейс при поднятом полном туннеле.

## D-005, уточнение. Разбор локализованных утилит по форме значения — 2026-10-24

Для утилит, у которых локализованы метки (и часть значений), а набор и порядок строк меняются между версиями Windows (`netsh wlan`, `pnputil`), поля определяются по форме значения (GUID, `NN%`, `802.11…`, число после известной строки и т. п.). Из меток используются только непереводимые (`SSID`, `BSSID`, `Rssi`). Если утилита ответила, а ожидаемое не распознано, — это ошибка источника (`Exception` «unrecognized output»), а не «данных нет» (ревью 001).

## D-010. Wi-Fi: приватность и разрешение на местоположение — 2026-10-24

Принято по ревью 001 (решения владельца).

- SSID своей сети собирается и маскируется при экспорте (D-006).
- BSSID своей точки доступа, MAC адаптера и список сохранённых профилей Wi-Fi не собираются: BSSID — геолокационный идентификатор, список профилей — история мест, MAC уже есть в `adapters`.
- Соседние сети — без SSID и BSSID: только диапазон, канал, сигнал, тип радио, загрузка канала.
- Сырой текст `netsh wlan` в снимок не кладётся (в нём SSID, BSSID, MAC).
- **На будущее** (проектирование сравнения снимков «до/после»): BSSID можно хранить как HMAC с локальной солью установки. Соль не экспортируется, при экспорте поле удаляется. Так значение сравнимо между снимками одного ПК и бесполезно для геолокации.
- **Разрешение на местоположение** (Windows 11 24H2+ требует его для данных WLAN): в GUI (этап 2) — только подсказка. Объяснить, зачем оно нужно; кнопка открывает `ms-settings:privacy-location`; само разрешение инструмент не переключает; после диагностики — напоминание выключить его обратно.
