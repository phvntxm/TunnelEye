# Журнал решений

Решения, которые меняют архитектуру или уточняют ТЗ. Новые — снизу.

## D-001. Единая схема снимка v1 — 2026-10-23

Каждый модуль сбора выдаёт конверт `tunneleye.module/1` (`schema`, `module`, `version`, `status`, `elevated`, `startedAt`, `durationMs`, `errors`, `data`); оркестратор собирает `snapshot.json` (`tunneleye.snapshot/1`) и кладёт рядом конверты модулей. Статусы: `ok`, `partial`, `failed`, `skipped`. Ошибки привязаны к источнику и классифицированы (`AccessDenied`, `NotSupported`, `NotFound`, `Timeout`, `Exception`).

Подробно: [schema/README.md](schema/README.md).

## D-002. Тесты связи: наружу только по явному согласию — 2026-10-23

Противоречие: ТЗ требует пинг внешних узлов, трассировку и резолв через разные DNS; CLAUDE.md запрещает сетевые запросы наружу.

Решение: модуль `connectivity` по умолчанию проверяет только локальное — шлюз, настроенные DNS-серверы, MTU до шлюза. Внешние узлы — только по явному флагу (CLI) или согласию пользователя (GUI); список адресов — в конфиге, не в коде.

## D-003. DNS-кэш: только агрегаты и подозрительное — 2026-10-23

DNS-кэш по сути — история посещений, которую ТЗ запрещает выносить в отчёт.

Решение: в снимок попадают число записей, доля ошибок и только записи, совпадающие с hosts или подозрительными адресами. Полный кэш — только в расширенном режиме.

## D-004. Каждый модуль — отдельный процесс — 2026-10-23

Оркестратор запускает каждый модуль в своём `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass` с таймаутом (по умолчанию 120 с); по таймауту убивается всё дерево процессов. Зависший, упавший или выдавший мусор модуль превращается в конверт `failed`, остальные не затрагиваются. Цена — около 0,5 с на запуск модуля.

`-ExecutionPolicy Bypass` действует только на дочерний процесс; политика машины не меняется (ТЗ: «не требуется отключать Execution Policy глобально»).

## D-005. Технические соглашения сбора — 2026-10-23

- JSON пишется через `System.Web.Script.Serialization.JavaScriptSerializer` (есть в .NET Framework 4.8), а не `ConvertTo-Json`: тот в PS 5.1 пишет enum числами, молча обрезает вложенность и разворачивает массивы из одного элемента. Перед сериализацией данные нормализуются (`ConvertTo-CollectorData`).
- Файлы — UTF-8 без BOM.
- Исходники `.ps1`/`.psm1` — только ASCII: PowerShell 5.1 читает файлы без BOM как ANSI. Проверяется тестом.
- Вывод консольных утилит декодируется с автоопределением (BOM → UTF-16 → строгий UTF-8 → OEM): утилита наследует кодовую страницу консоли родителя, и она бывает и 866, и 65001.
- Приоритет источников: командлеты → CIM → реестр → `netsh` (локализован; разбор + исходный текст в `raw`).
- Тесты — встроенный Pester 3.4, ничего не устанавливается.
