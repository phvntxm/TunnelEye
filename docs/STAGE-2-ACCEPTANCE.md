## Что ещё требуется для приёмки

Заполнять результаты отдельно для Windows 10 и Windows 11. Если сценарий не запускался, ставить «не проверено», а не считать синтетический тест стендовым.

| Проверка | Windows 10 | Windows 11 | Что сохранить локально |
| --- | --- | --- | --- |
| Чистое состояние: полный снимок с администратором за ≤ 3 мин | Не подтверждено | Не подтверждено в итоговой матрице | Версия приложения, сборка ОС, время, статусы 13 модулей |
| Снимок без администратора, явная отметка ограничений | Не подтверждено | Ранее представлены отчёты; требуется связать с версией/ОС стенда | Снимок и перечень ожидаемых ограничений |
| Отказ UAC → ровно один запуск без администратора | Не подтверждено | Нет отдельного протокола | Результат запуска и пометка прав |
| Другая административная учётная запись | Не подтверждено | Не подтверждено | Доступ к каталогу, elevatedAsOtherUser, HKCU-проверки «не проверено» |
| Сбой одного модуля не ломает остальные | Не подтверждено | Не подтверждено на ОС стенда | Итоговый снимок и статусы модулей |
| Пять приёмочных проблем ниже | Не подтверждено | Не подтверждено в итоговой матрице | Отдельный снимок и ожидаемые находки для каждого случая |
| Открытие отчёта и HTML без сети, RU/EN, маскировка | Не подтверждено на ОС стенда | Есть ручное подтверждение HTML; остаётся привязка к стенду | Отчёты и короткий протокол |

Снимки с реальных ВМ нужны исходными для анализа и только локально. Маскированный snapshot с псевдонимами IP не анализировать повторно как эквивалент исходного; маскированные отчёты предназначены для просмотра и передачи.

## Пять приёмочных проблем из ТЗ

Каждый случай проверяется отдельно от чистой контрольной точки ВМ; после него — возврат к ней. Настройки основной машины не менять. В этом документе перечислены ожидаемые наблюдения, команды изменения сети не запускаются.

| Сценарий | Ожидаемое правило | Что проверить кроме срабатывания |
| --- | --- | --- |
| Два действующих шлюза с близкими метриками на обычных подключениях | `two-gateways` | На чистой конфигурации находки нет; не спутать с штатной маршрутизацией полного VPN |
| Включённый прокси на заведомо неработающий локальный endpoint ВМ | `dead-proxy` | Выключенная запись прокси не даёт находку; проверка относится к нужному пользователю |
| Полный VPN-туннель и DNS через физический интерфейс | `dns-leak` | Сравнить защищённую и незащищённую конфигурации; правило остаётся экспериментальным до проверки и отдельного решения |
| Остаток TAP от удалённого клиента | `vpn-leftovers` | Установленный Wintun без созданного адаптера сам по себе не остаток |
| Перенаправление чувствительного домена в hosts | `hosts-sensitive` | Доказательство с адресом и источником; блокировка на loopback/неопределённый адрес — отдельное правило `hosts-sensitive-blocked` |

Синтетические аналоги уже есть в `tests/snapshots/`: `two-gateways`, `dead-proxy`, `dns-leak`, `vpn-leftovers`, `hosts-sensitive`. Они подтверждают регрессию ядра, а не готовность Windows-стенда. Проверку DNS-утечки планировать отдельно: любые внешние тесты связи требуют явного согласия владельца; без него внешний режим не включать.

## Формат передачи результатов

Для каждой ОС и каждого случая сохранить:

1. Версию/коммит приложения, сборку ОС, режим прав и имя сценария.
2. Исходный snapshot в `.local/regress/`, например `win11-two-gateways.json`.
3. Рядом — `win11-two-gateways.expected.json` с ожидаемыми и запрещёнными находками:

```json
{
  "present": ["two-gateways"],
  "absent": ["dead-proxy", "hosts-sensitive"]
}
```

4. HTML/JSON-отчёт, время сбора и краткий результат ручной проверки. Скриншот без описания режима не подтверждает отдельные сценарии UAC.

Существующий `RegressionTests.Local_real_snapshots_match_their_expectations` автоматически читает эту пару. Пустой каталог локального регресса или снимок без expected-файла не подтверждает, что ожидаемые находки проверены. Не добавлять реальные данные в Git даже после маскировки.

На машине разработки проверить импортированные результаты можно из корня репозитория:

```powershell
dotnet test src/TunnelEye.sln --no-restore --filter FullyQualifiedName~Local_real_snapshots_match_their_expectations --verbosity minimal -m:1
```

Админские тесты запускает владелец внутри соответствующей ВМ: `tests/Invoke-AdminTests.ps1`. Результат `.local/test-results.xml` перед следующим запуском сохранить с обозначением ОС, чтобы не затереть предыдущий протокол. Установка SDK/тестовых зависимостей на чистую ВМ не является требованием к пользователю продукта; собранный каталог GUI переносится отдельно, тестовый запуск — отдельная проверка разработчика.
