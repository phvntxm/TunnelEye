# Окно TunnelEye — часть 2.4

## Сборка и запуск

```powershell
dotnet restore src/TunnelEye.sln
dotnet build src/TunnelEye.sln
src/TunnelEye.App/bin/Debug/net48/TunnelEye.exe
```

Для открытия полноценного сохранённого снимка при запуске:

```powershell
src/TunnelEye.App/bin/Debug/net48/TunnelEye.exe --open snapshot.json
```

Наложения из tests/snapshots нужно сначала развернуть `tests/Expand-Overlay.ps1`. Само открытие снимка не запрашивает UAC и не запускает сбор.

## Поведение

- RU по умолчанию; переключатель RU/EN перестраивает отчёт из уже выполненного анализа, повторного сбора нет. Подписи — `.resx`.
- «Диагностика» запускает отдельный Windows PowerShell через UAC, окно остаётся отзывчивым. Отказ в UAC — один повтор с правами исходного пользователя, с видимой пометкой.
- Согласие на внешние тесты относится только к одному запуску и сбрасывается. По умолчанию выключено. Передаётся LaunchingUserSid, поэтому сбор под другой учётной записью отмечается по D-015.
- Новые снимки — `%LOCALAPPDATA%/TunnelEye/snapshots/<дата-GUID>/snapshot.json`. Каталог исходного пользователя создаётся до UAC; под другой учётной записью нужно проверить доступ на стенде.
- Прогресс читается из progress.jsonl; частичная строка UTF-8 или занятый файл не роняют окно. Модули ограничены оркестратором по 120 с. После 30 мин появляется пометка о медленном сборе, процесс не бросается.
- Пока идёт операция, закрытие окна отклоняется. Обычный процесс не может надёжно завершить дерево повышенного PowerShell, поэтому кнопки фиктивной отмены нет.
- В сводке постоянно показаны права исходного сбора: с администратором, без него либо неизвестно для старого снимка. Пометка сохраняется при открытии файла и в экспорте.
- Встроенные VPN-профили Windows показаны отдельным разделом от сторонних клиентов: имя, состояние, сервер, тип туннеля, раздельное туннелирование и технические детали.
- Сводка, рекомендации, доказательства с группировкой hosts, неполные проверки; вкладки сети, графиков, служб, железа и статусов модулей. Схема сети показывает отношения адаптер → шлюз → префикс, без выводов о сети за пределами ПК.
- OxyPlot.Core/Wpf/Wpf.Shared 2.2.0 закреплены в проекте и packages.lock.json; MIT-лицензия — THIRD-PARTY-NOTICES. В дистрибутив не входят тестовые зависимости.
- Экспорт HTML/JSON: маскировка включена по умолчанию, исходный открытый снимок перезаписать отчётом нельзя. Просмотр в WPF — нативный текст, не HTML-браузер.
- Настройки местоположения предлагаются при AccessDenied у Wi-Fi. Кнопка открывает системную страницу, сама разрешения не меняет и напоминает выключить их после проверки.

## Доказательства (запрос 012)

В находке раскрывается список адресных групп. Для hosts — домен, адрес или его псевдоним и путь к источнику в снимке. Для остальных фактов — параметр, значение и источник; неизвестные будущие поля показываются с техническим именем параметра. Булевы значения и отсутствие данных локализованы. Технические имена источников сохраняются для проверки происхождения факта.

Таблицы WPF ограничены по высоте, поддерживают прокрутку и перенос значений, строки виртуализируются. Содержимое создаётся при раскрытии группы. HTML имеет прокручиваемую область с заголовками столбцов; строки не обрезаются. Внутри каждой группы отдельно раскрывается «Технический JSON», по умолчанию закрытый. Обе формы используют тот же отчёт, в том числе после маскировки; исходные данные не изменяются.

Проверочный рендер с открытыми таблицами и закрытым JSON:

```powershell
powershell.exe -NoProfile -STA -File tools/Preview-App.ps1 -OutputPath .local/evidence-ru.png -SnapshotPath .local/synthetic.json -BinaryDirectory .local/evidence-build -ExpandEvidence -ScrollOffset 650
```

Файл 012 подтверждает ручное отображение отметок прав и маскированного HTML с диаграммой и раскрытием. Проверка под другой административной учётной записью и стенд Windows 10/11 по-прежнему требуются для приёмки этапа 2. Применение рекомендаций относится к этапу 4.


## Графитовый интерфейс и Аргус (согласовано по макетам 014)

Тёмно-серые поверхности и оранжевые акценты применены к окну, боковым вкладкам, таблицам, раскрытиям, техническим данным и OxyPlot-графикам. Уровни проблем сохраняют отдельные цвета и текстовые подписи. Иконка компилируется из оригинального `Assets/Argus.xaml`; при сборке встроенный PowerShell создаёт ICO в obj, без новых зависимостей и бинарных исходников.

Во время диагностики показаны пять абстрактных глаз. Их движение декоративное: название модуля, число завершённых/общее и полоса берутся только из событий сборщика. До первого события — ожидание/UAC, без расчётного процента. Нижняя строка состояния находится вне прокрутки. При отмене UAC сохраняется отметка ограниченного сбора; ошибки отдельных модулей не останавливают остальных.

«Анимации Аргуса» включены по умолчанию; переключатель работает и во время сбора, выбор действует в текущем сеансе окна. Системная настройка клиентских анимаций имеет приоритет. При её отключении, ручном выключении или остановке — статичный знак. В конце таймер останавливается; затухание не задерживает готовый отчёт. Обработчики освобождаются при выгрузке/закрытии. Общая ошибка остаётся на экране с возможностью повторить диагностику или открыть снимок.

HTML использует ту же тёмную палитру, при печати переключается на белый фон с тёмным текстом и полной высотой доказательств. Маскировка включена по умолчанию, JSON и CSP сохранены. Аудио пока не подключено. Системные исправления — этап 4.

Проверочный рендер настоящего окна с состоянием-фикстурой (без сбора и UAC):

```powershell
powershell.exe -NoProfile -STA -File tools/Preview-App.ps1 -OutputPath .local/argus.png -DiagnosisState Collecting -Language ru
powershell.exe -NoProfile -STA -File tools/Preview-App.ps1 -OutputPath .local/argus-static.png -DiagnosisState Limited -DisableAnimations -Language en
```

Возможные состояния: Waiting, Collecting, Limited, Error. Автотесты отдельно проходят полный путь окна с подставным runner: ожидающий запуск, события, ошибка, повтор, игнорирование старых событий, открытие готового отчёта. Настоящий UAC и другой администратор — проверки владельца; итоговая приёмка требует стенда Windows 10/11.
