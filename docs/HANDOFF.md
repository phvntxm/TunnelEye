## Материал для этапа 2

- **«Линк ниже возможностей» (Wi-Fi)** сравнивает три вещи: возможности карты (`wifi.drivers[].radioTypesSupported`), тип радио своей точки (`wifi.neighbors.bss[connected = true].radioType`) и фактический линк (`wifi.interfaces[].radioType`).
  - Карта ax, точка ac → «Совет: ограничивает роутер» (машина разработки: AX210 на роутере Wi-Fi 5).
  - Точка ax, линк ac → проблема на стороне клиента (драйвер, настройки адаптера) — уровень выше.
- **«Wi-Fi выключен»**: модуль `wifi` не различает выключенный радиомодуль и режим «в самолёте» — опираться на `adapters` и причину `skipped` модуля `wifi`.
- **Разрешение на местоположение** (D-010): в GUI только подсказка с кнопкой `ms-settings:privacy-location` и напоминание выключить после диагностики; сами не переключаем.

## Ключевые решения

- **D-001** — единый конверт модуля `tunneleye.module/1` и снимок `tunneleye.snapshot/1`; статусы `ok` / `partial` / `failed` / `skipped`; ошибки привязаны к источнику.
- **D-002** — тесты связи наружу только по явному согласию; по умолчанию только локальное.
- **D-003** — DNS-кэш: только агрегаты и подозрительное.
- **D-004** — каждый модуль в отдельном `powershell.exe` с таймаутом; `-ExecutionPolicy Bypass` только для дочернего процесса.
- **D-003, уточнение (принято)** — совпадения DNS-кэша с hosts хранятся только счётчиком `fromHosts`; списком — ответы-«чёрные дыры» для имён не из hosts.
- **D-005** — технические соглашения: `JavaScriptSerializer` вместо `ConvertTo-Json`, UTF-8 без BOM, исходники `.ps1` только ASCII, автоопределение кодировки вывода утилит, тесты на встроенном Pester 3.4.
- **D-006** — «Экспорт без личных данных» маскирует также DNS-суффиксы и SSID (ТЗ обновлено с согласия владельца).
- **D-007** — правила этапа 2: IPv6 DNS `fec0:0:0:ffff::1-3` игнорируются; hosts — обход блокировок («Совет», проверить актуальность) отдельно от подмены («Важно»); нужна пара обезличенных фикстур proxy/TUN для теста DNS-утечки — снимается на виртуалке стенда (ТЗ обновлено по hosts).
- **D-008** — «Экспорт без личных данных» маскирует также имена VPN-профилей и адреса VPN-серверов (ТЗ обновлено с согласия владельца).
- **D-009** — соединения: публичные удалённые адреса не хранятся, только счётчики «процесс + локальный адрес + удалённый порт» с числом уникальных адресов; соединения ядер VPN через физический интерфейс — сам туннель, не утечка.
- **D-005, уточнение** — локализованные утилиты разбираются по форме значения, из меток — только непереводимые; нераспознанный ответ — ошибка, а не «данных нет».
- **D-010** — Wi-Fi: без BSSID, MAC, профилей и сырого `netsh`, соседи без SSID/BSSID; на будущее — BSSID как HMAC с локальной солью; разрешение на местоположение — только подсказка в GUI.

## Находки, которые легко забыть

**PowerShell 5.1**
- `ConvertTo-Json` пишет enum числами, обрезает вложенность и разворачивает массивы из одного элемента — поэтому свой сериализатор.
- Объекты из `New-Object` приходят в обёртке PSObject и ломают сериализацию — коллекции создаются через `::new()`.
- `$x = if (...) { @(...) }` теряет массивы (`@()` → `$null`, один элемент → скаляр) — писать `$x = $null; if (...) { $x = @(...) }`.
- Параметр `[string]` превращает `$null` в `''` — для «может быть null» параметр без типа.
- `.BaseObject` под StrictMode у PSCustomObject падает — использовать `.PSObject.BaseObject`.
- Многие `Net*`-командлеты сообщают «пусто» ошибкой ObjectNotFound — `Invoke-AllowNotFound`.
- Кавычки в аргументах внешних программ искажаются — сообщение коммита передавать через файл (`git commit -F`).

**Кодировки консольных утилит**
- `netsh` пишет в кодовой странице унаследованной консоли: 866 в новой консоли, 65001 после `chcp 65001`.
- `pnputil` при перенаправленном выводе пишет в **ANSI 1251**, а не OEM 866. Язык вывода тоже зависит от окружения (тот же `pnputil` отвечал то по-английски, то по-русски).
- Декодер (`ConvertFrom-NativeBytes`): BOM → UTF-16 → строгий UTF-8 → лучшая по оценке из OEM и ANSI (буквы против псевдографики). Парсеры не опираются на метки.

**pnputil**
- Поля берутся по позиции; строка «дата версия» ищется после GUID, потому что у некоторых классов есть лишняя строка «Версия класса».
- Сверка на реальном русском выводе: 18 пакетов класса Net, все разобраны полностью, `driverDate = null` — 0. Реальная обезличенная фикстура в cp1251: `tests/collectors/fixtures/pnputil-enum-drivers-ru.cp1251.txt` (байты защищены `.gitattributes`).

**Маршрутизация**
- `Find-NetRoute` — локальный запрос к таблице маршрутов, пакеты не отправляются. Внешние цели — документационные адреса `192.0.2.1` и `2001:db8::1`; «сеть недоступна» (Win32 1231) — результат `reachable = false`, а не ошибка.
- Эффективная метрика = метрика маршрута + метрика интерфейса; хранится в маршрутах и в `routeSelection`.
- **Два маршрута по умолчанию** на машине разработки: через `happ-tun` (sing-tun, Wintun) и через Wi-Fi, оба с метрикой маршрута 0. У `happ-tun` Windows не сообщает метрику интерфейса (`null`), но выбирает именно его для внешнего IPv4. Правило «два шлюза» на этапе 2 должно опираться на `routeSelection`, а не только на метрики, иначе полный VPN-туннель даст ложное срабатывание.
- Список ICS (`HNetCfg`) без прав администратора пуст; частная сторона ICS находится по `scopeAddress` (обычно `192.168.137.1`).

**Материал для правил этапа 2 (с машины разработки)**
- Адаптеры Fortinet, отсутствующий Cisco AnyConnect, Kerio, Wintun; пакет драйвера TAP-Windows в хранилище без адаптера — остаток.
- Встроенные драйверы Microsoft датированы 2006-06-21 — правило «устаревший драйвер» должно их исключать.
- hosts: 200 имён на один адрес и 35 на адреса Telegram — по D-007 это обход блокировок («Совет»), а не подмена.
- Прокси `127.0.0.1:10809` в HKCU прописан, но выключен — правилу «мёртвый прокси» учитывать флаг включения.
- Windows загружает hosts в DNS-кэш целиком.
- У интерфейсов без настроенного DNS Windows сообщает для IPv6 заглушки `fec0:0:0:ffff::1..3` (устаревшие site-local) — правила их игнорируют (D-007).
- `Get-DnsClientServerAddress` может вернуть один и тот же сервер дважды (link-local IPv6 роутера) — модуль пишет как есть, правилам не считать это двумя серверами.
- Встроенный список DoH Windows 11 (12 шаблонов Cloudflare/Google/Quad9) присутствует всегда — это не признак включённого DoH; включённость — по `doh.interfaces` и `doh.policy`.
- При приёмке `dns-proxy` туннеля не было (`happ-tun` отсутствовал). На машине разработки Happ работает без системного прокси и без TUN, поэтому DNS-утечку проверяем на виртуалке стенда (D-007, п. 3).
- `vpn` на машине разработки: 3 встроенных профиля (SSTP со split tunneling, Automatic, L2TP/PSK), клиенты Cisco Secure Client (адаптер `Not Present`, служба остановлена), FortiClient (драйверы-фильтры `FortiFilter`, `FortiTransCtrl` работают), Kerio (служба работает), Cloudflare WARP (остановлен), Happ (служба и процессы работают), zapret2 (служба из профиля пользователя) с работающим драйвером WinDivert; драйверы TAP-Windows и Wintun установлены без адаптеров. Материал для «Конфликт VPN», «Лишние службы», «Конфликт VPN и блокировок».
- Ядро `xray` Happ запускает отдельным процессом (родитель — `Happ.exe`, файл в `Happ\core\`). Оно в общей записи `proxy-core`; с правами админа `owners` привязывает его к Happ по родительскому процессу или папке, без админа `owners = null` и связь ищет анализатор.
- Имена VPN-профилей и адреса серверов указывают на организации — в фикстуры только обезличенными, при экспорте маскируются (D-008).- `firewall` на машине разработки: 639 правил (381 включено), все три профиля включены (входящие — Block). WFP: 1190 фильтров, 104 callout-драйвера, 18 провайдеров. Сторонние провайдеры: Fortinet (7 фильтров, служба `FortiTransCtrl`), WinDivert (провайдер есть, а его 15 фильтров — без `providerKey`, связь только через callout), **Check Point — провайдер зарегистрирован без фильтров и без клиента в `vpn`** — материал для «остатков старых VPN».

NDIS-фильтр `ft_fortifilter` (FortiClient) — `modifying`, включён на всех 12 привязках; остальные фильтры — Microsoft.
