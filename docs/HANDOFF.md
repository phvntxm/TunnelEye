## Материал для этапа 2

- **«Линк ниже возможностей» (Wi-Fi)** сравнивает три вещи: возможности карты (`wifi.drivers[].radioTypesSupported`), тип радио своей точки (`wifi.neighbors.bss[connected = true].radioType`) и фактический линк (`wifi.interfaces[].radioType`).
  - Карта ax, точка ac → «Совет: ограничивает роутер».
  - Точка ax, линк ac → проблема на стороне клиента (драйвер, настройки адаптера) — уровень выше.
- **«Wi-Fi выключен»**: модуль `wifi` не различает выключенный радиомодуль и режим «в самолёте» — опираться на `adapters` и причину `skipped` модуля `wifi`.
- **Разрешение на местоположение** (D-010): в GUI только подсказка с кнопкой `ms-settings:privacy-location` и напоминание выключить после диагностики; сами не переключаем.
- **«Два шлюза»** — опираться на `routing.routeSelection`, а не только на метрики: при полном VPN-туннеле два маршрута по умолчанию с метрикой 0 — норма, а метрика интерфейса TUN бывает неизвестна.
- **«Остатки старых VPN» / «Лишние службы»** — признаки:
  - адаптер `Not Present`;
  - пакет драйвера TAP/Wintun в хранилище без адаптера;
  - провайдер WFP без фильтров и без клиента в `vpn.clients`;
  - служба, задача или автозапуск с `imageExists = false`.
- **«Открытые порты»** — порт на всех интерфейсах в профиле `Public` опасен, только если входящие для него разрешены правилом брандмауэра (по умолчанию входящие в Public блокируются).
- **«Трафик мимо туннеля»** — соединения ядер прокси и VPN-клиентов через физический интерфейс — сам туннель (D-009).

## Находки, которые легко забыть

**PowerShell 5.1**
- `ConvertTo-Json` пишет enum числами, обрезает вложенность и разворачивает массивы из одного элемента — поэтому свой сериализатор.
- Объекты из `New-Object` приходят в обёртке PSObject и ломают сериализацию — коллекции создаются через `::new()`.
- `$x = if (...) { @(...) }` теряет массивы (`@()` → `$null`, один элемент → скаляр) — писать `$x = $null; if (...) { $x = @(...) }`. То же в литерале хэш-таблицы: `key = if (...) { $array }`.
- Параметр `[string]` превращает `$null` в `''` — для «может быть null» параметр без типа.
- `.BaseObject` под StrictMode у PSCustomObject падает — использовать `.PSObject.BaseObject`.
- Многие `Net*`-командлеты сообщают «пусто» ошибкой ObjectNotFound — `Invoke-AllowNotFound`.
- Кавычки в аргументах внешних программ искажаются — сообщение коммита передавать через файл (`git commit -F`).
- Внутри вызова метода `-replace 'a', 'b'` запятая разделяет аргументы метода — выражение брать в скобки.
- Оператор `foreach (...) { }` нельзя продолжить конвейером (`} | Sort-Object` — ошибка разбора) — сначала в переменную.
- `$Matches` перезаписывается любым `-match` во вложенном вызове — сохранять группу сразу.
- Ошибка .NET-метода (например, `XmlReader.Create`) не останавливает скрипт при умолчательном `ErrorActionPreference` — оборачивать в `try { } catch { throw }`.
- Рекурсивные функции, возвращающие массивы, копируют их на каждом уровне — на данных в ~1 МБ это секунды; обход со стеком.
- Pester 3.4: функцию, возвращающую массив через `, @(...)`, в тесте не оборачивать ещё раз в `@()` — получится массив в массиве.

**Кодировки и локализация консольных утилит**
- `netsh` пишет в кодовой странице унаследованной консоли: 866 в новой консоли, 65001 после `chcp 65001`. Язык меток тоже зависит от окружения: под сборщиком — язык системы, в консоли разработчика может быть английский. Сопоставлять по меткам нельзя.
- `pnputil` при перенаправленном выводе пишет в **ANSI 1251**, а не OEM 866. Язык вывода тоже зависит от окружения.
- Декодер (`ConvertFrom-NativeBytes`): BOM → UTF-16 → строгий UTF-8 → лучшая по оценке из OEM и ANSI (буквы против псевдографики). Парсеры не опираются на метки.
- Консоль администратора открывается в `C:\Windows\System32` — относительные пути из команд для владельца уходят туда; давать абсолютные или с `Set-Location` на репозиторий.

**pnputil**
- Поля берутся по позиции; строка «дата версия» ищется после GUID, потому что у некоторых классов есть лишняя строка «Версия класса».
- Реальная обезличенная фикстура в cp1251: `tests/collectors/fixtures/pnputil-enum-drivers-ru.cp1251.txt` (байты защищены `.gitattributes`).

**Маршрутизация**
- `Find-NetRoute` — локальный запрос к таблице маршрутов, пакеты не отправляются. Внешние цели — документационные адреса `192.0.2.1` и `2001:db8::1`; «сеть недоступна» (Win32 1231) — результат `reachable = false`, а не ошибка.
- Эффективная метрика = метрика маршрута + метрика интерфейса; хранится в маршрутах и в `routeSelection`.
- У TUN-адаптеров на Wintun Windows может не сообщать метрику интерфейса (`null`), но выбирать именно их для внешнего трафика.
- Список ICS (`HNetCfg`) без прав администратора пуст; частная сторона ICS находится по `scopeAddress` (обычно `192.168.137.1`).

**Драйверы**
- Встроенные драйверы Microsoft датированы 2006-06-21 — правило «устаревший драйвер» должно их исключать.

**DNS, прокси, hosts**
- Прокси в HKCU может быть прописан, но выключен — правилу «мёртвый прокси» учитывать флаг включения.
- Windows загружает hosts в DNS-кэш целиком.
- У интерфейсов без настроенного DNS Windows сообщает для IPv6 заглушки `fec0:0:0:ffff::1..3` (устаревшие site-local) — правила их игнорируют (D-007).
- `Get-DnsClientServerAddress` может вернуть один и тот же сервер дважды (link-local IPv6 роутера) — модуль пишет как есть, правилам не считать это двумя серверами.
- Встроенный список DoH Windows 11 (шаблоны Cloudflare/Google/Quad9) присутствует всегда — это не признак включённого DoH; включённость — по `doh.interfaces` и `doh.policy`.

**VPN**
- Клиенты-прокси запускают ядро (`xray`, `sing-box`) отдельным процессом: родитель — процесс клиента, файл — в папке клиента. Без прав админа пути чужих процессов не видны — поэтому `owners` только под админом.
- Имена встроенных VPN-профилей и адреса серверов часто указывают на организацию — в фикстуры только обезличенными, при экспорте маскируются (D-008).

**Firewall и WFP**
- Windows вшивает путь к программе в имя правила брандмауэра (`TCP Query User{guid}C:\users\<имя>\…`) — `Hide-UserProfilePath` (общий модуль) заменяет папку профиля в любом месте строки.
- `netsh wfp show state` пишет в один файл несколько корневых элементов (`<wfpstate>`, затем `<firewallState>`) — обычный `[xml]` падает, читать через `XmlReader` с `ConformanceLevel = Fragment`. В `<sessions>` — имена пользователей, в `<aleConnectedEndpoints>` — соединения: не собираются.
- Фильтры WinDivert идут без `providerKey` — связь с ним только через callout.

**Службы**
- Windows кладёт SID пользователя в пути задач планировщика (`\<папка>\S-1-5-21-…\`), а `Principal.UserId` — имя пользователя: SID заменяется на `%USERSID%` (`Hide-UserProfilePath`), учётные записи хранятся классом.
- Встроенные NDIS-фильтры Microsoft не пишут `Ndi\FilterType`/`FilterRunType`, только `Ndi\Interfaces\FilterMediaTypes` — по нему и определяется, что компонент — фильтр.

**TCP-стек**
- `MTU = 0` в `Tcpip\Parameters\Interfaces\{guid}` пишут некоторые VPN-клиенты — это не твик.

**Wi-Fi**
- `netsh wlan` локализован полностью, включая форму значений («2,4 ГГц», дата в формате культуры), русские метки переносятся на следующую строку; поля — по форме значения. Дата драйвера похожа на версию (`\d+(\.\d+)+`) — отделять первой.

**Журналы событий**
- Журнал System за неделю может содержать десятки тысяч событий несетевых провайдеров (коммутатор Hyper-V, сторонние службы) — читать целиком дорого (секунды), отбирать XPath по провайдерам.
- `-FilterHashtable` с несуществующим `ProviderName` падает целиком, XPath — нет.
- Провайдер событий драйвера адаптера — имя его **службы**; часто совпадает с именем файла драйвера без `.sys`, но не всегда (у Realtek файл с суффиксом `x64`, служба без) — брать оба.
- Журнал отвергает XPath больше чем с ~21 условием на провайдера («The specified query is invalid») — запрашивать частями.
- Ошибки встроенного VPN (SSTP, L2TP, IKEv2) — в журнале Application, провайдер `RasClient`, а не в System.
- `Get-NetAdapter -Physical` не считает физическими минипорты VPN-клиентов, а `Win32_NetworkAdapter.PhysicalAdapter` — считает.
- Тесты, проверяющие JSON на «запрещённые» ключи, применять к `data`, а не ко всему конверту: у `errors[]` есть ключ `message`.

**Железо**
- `Win32_VideoController.AdapterRAM` — 32-битное поле: видеопамять больше 4 ГБ показывается как ~4 ГБ. Точный объём — `HardwareInformation.qwMemorySize` в ключе драйвера класса `{4d36e968-…}`.
- Ключ класса устройств (`Control\Class\{guid}`) содержит подраздел `Properties`, закрытый для обычного пользователя: `Get-ChildItem` по классу падает — открывать подразделы `0000`, `0001`, … по одному.
- `Win32_PhysicalMemory.Speed` показывает текущую скорость, а не номинал модуля: выключенный профиль XMP/EXPO по WMI не виден — только по part number и базе моделей.
- `Win32_SystemSlot` (SMBIOS) у многих плат неполон — подсказка, а не перечень слотов.
- Чипсет в WMI не виден (через PnP — безымянный «мост PCI — ISA»); выводится по модели платы.
- Под работающим гипервизором (Hyper-V, VBS, WSL 2) Windows — гость: флаги виртуализации `Win32_Processor` (`VirtualizationFirmwareEnabled`, `VMMonitorModeExtensions`, SLAT) могут читаться как `False`. Смотреть `Win32_ComputerSystem.HypervisorPresent`; иначе — ложный совет «включи VT-x».
- `Win32_Processor.SocketDesignation` часто не сокет, а метка на плате (`U3E1`, `CPU 1`) — сокет по модели CPU.
