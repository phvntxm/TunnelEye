# Ревью 001 — модуль `wifi`

Модуль: `collectors/wifi.ps1` 1.0.0. Схема: [docs/schema/wifi.md](../schema/wifi.md). Тесты: `tests/collectors/Wifi.Tests.ps1`, фикстуры `tests/collectors/fixtures/wlan-*.txt`. Дата: 2026-10-24.

## Сделано

- **`interfaces[]`** из `netsh wlan show interfaces`: имя, модель, GUID (в формате модуля `adapters`), подключён ли, SSID, диапазон, канал, тип радио, проверка подлинности, шифр, скорости приёма и передачи, сигнал в %, RSSI.
- **`drivers[]`** из `netsh wlan show drivers`: драйвер, производитель, версия, дата (ISO), поддерживаемые типы радио и диапазоны, поддержка WPA3.
- **`neighbors`** из `netsh wlan show networks mode=bssid` (последнее сканирование, новое не запускается): число сетей и точки доступа с диапазоном, каналом, сигналом, типом радио, загрузкой канала (BSS Load) и числом клиентов — без SSID и BSSID; своя точка помечена `connected`.
- **Разбор `netsh` по форме значений, а не по меткам.** Метки локализованы, переносятся на новую строку, набор строк разный в Windows 10 и 11 24H2. Проверено на обезличенном реальном выводе русской и английской Windows 11 и на раскладке Windows 10.
- **Статусы:**
  - `skipped` — нет или не запущена `WlanSvc`, либо нет Wi-Fi-интерфейса;
  - `AccessDenied` — нет разрешения на доступ к местоположению (Windows 11 24H2+);
  - прочие ненулевые коды выхода `netsh` — ошибка `Exception`.
- **На машине разработки:** `ok`, ~0,7 с, ~1 КБ; снимок из 10 модулей ~29 с. Карта AX210 (802.11ax, 6 ГГц), подключение 802.11ac на 5 ГГц, канал 44, сигнал 72–80 %, загрузка канала 15 %. Материал для правила «линк ниже возможностей»: ограничивает, похоже, роутер Wi-Fi 5.

## Отклонения от TZ.md

1. **Дополнительный источник.** ТЗ называет для Wi-Fi `netsh wlan show interfaces` и `show drivers`. Добавлен `netsh wlan show networks mode=bssid`: без соседних точек правило «загруженный канал 2,4 ГГц» (ТЗ, таблица правил) не посчитать.
2. **Не собираются BSSID своей точки и MAC адаптера.** ТЗ их не требует явно; BSSID — геолокационный идентификатор, MAC уже есть в `adapters`.
3. **Сырой текст `netsh` в снимок не кладётся** (в других модулях `raw` есть, D-005): в нём SSID, BSSID и MAC.

## Кандидаты в DECISIONS.md

1. **D-010 (предлагается). Wi-Fi: приватность.**
   - SSID своей сети собирается и маскируется при экспорте (D-006).
   - BSSID своей точки, MAC адаптера и список сохранённых профилей не собираются.
   - Соседние сети — без SSID и BSSID: только диапазон, канал, сигнал, тип радио, загрузка.
   - Сырой текст `netsh wlan` в снимок не кладётся.
2. **Уточнение D-005.** Для локализованных утилит с плавающим набором строк (`netsh wlan`) поля определяются по форме значения; из меток используются только непереводимые (`SSID`, `BSSID`, `Rssi`). Так уже сделано для `pnputil`, стоит записать как общее правило.

## Открытые вопросы ревьюеру

1. **BSSID.** Без него нельзя отличить роуминг между точками одной mesh-сети в снимках «до/после». Варианты:
   - оставить как есть;
   - хранить номер точки внутри снимка (`apIndex`) — несравним между снимками;
   - хранить хэш BSSID с солью снимка — тоже несравним.

   Решает владелец.
2. **Нет разрешения на местоположение.** Сейчас модуль пишет `AccessDenied`, данных Wi-Fi нет. Нужно ли на этапе 2 в GUI подсказывать пользователю включить разрешение (и только на время диагностики)? Решает владелец.
3. **Не проверено вживую:**
   - Windows 10;
   - машина без Wi-Fi (`skipped`);
   - выключенное разрешение на местоположение;
   - адаптер с двумя интерфейсами.

   Покрыто только фикстурами; предлагается проверить на ВМ стенда.
4. **Модель Wi-Fi-карты в фикстурах.** В фикстурах осталась модель (Intel AX210) и путь к DLL драйвера заменён на выдуманный. Модель — сведения о железе, а не о человеке; оставить?
