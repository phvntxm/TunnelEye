## Обязательные правки

1. **Тихий `skipped` при нераспознанном выводе.** Сейчас, если `netsh wlan show interfaces` вернул текст, а парсер нашёл 0 интерфейсов, модуль пишет «No Wi-Fi interface» — при новой раскладке `netsh` (следующая сборка Windows) мы молча потеряем Wi-Fi и выдадим неверный диагноз.
   - Наличие Wi-Fi определять не по тексту, а по адаптерам: `Get-NetAdapter -Physical`, `NdisPhysicalMedium -eq 9` (Native 802.11).
   - Нет такого адаптера → `skipped` (как сейчас).
   - Адаптер есть, но отключён → `skipped` с причиной «адаптер отключён».
   - Адаптер включён, `netsh` ответил, а парсер дал 0 интерфейсов → ошибка `Exception` «unrecognized netsh output», данные `drivers`/`neighbors` собирать дальше, статус `partial`.
   - Тест: фикстура с мусорным/незнакомым текстом при «есть адаптер» → не `skipped`.
2. **Дата драйвера и культура.** `netsh` форматирует дату по культуре пользователя. Список форматов `M/d/yyyy` до `dd/MM/yyyy` неверно разберёт en-GB и подобные (`03/12/2026` → 12 марта вместо 3 декабря).
   - Сначала `TryParseExact` по `[CultureInfo]::CurrentCulture.DateTimeFormat.ShortDatePattern` (дочерний `powershell.exe` наследует ту же культуру, что и `netsh`), затем текущий список как запасной.
   - Тест: en-GB, `03/12/2026` → `2026-12-03`.

## Материал для этапа 2 (в HANDOFF)

- Правило «линк ниже возможностей» сравнивает три вещи: возможности карты (`drivers.radioTypesSupported`), тип радио своей точки (`neighbors.bss[connected=true].radioType`) и фактический линк (`interfaces.radioType`).
  - Карта ax, точка ac → «Совет: ограничивает роутер» (случай машины разработки: AX210 на роутере Wi-Fi 5).
  - Точка ax, линк ac → проблема на стороне клиента (драйвер/настройки адаптера) — уровень выше.
- Выключенный радиомодуль / режим «в самолёте» модуль `wifi` не различает — для правила «Wi-Fi выключен» опираться на `adapters` и причину `skipped` из п. 1.
