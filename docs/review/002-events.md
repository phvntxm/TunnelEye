# Ревью 002 — модуль `events`

Модуль: `collectors/events.ps1` 1.0.0. Схема: [docs/schema/events.md](../schema/events.md). Тесты: `tests/collectors/Events.Tests.ps1`. Дата: 2026-10-24.

Перед модулем выполнены правки по [ответу на ревью 001](001-wifi.reply.md) — `wifi` 1.1.0, коммит `65c850d`:
- наличие Wi-Fi по адаптерам, нераспознанный вывод `netsh` — ошибка и `partial`;
- дата драйвера по культуре;
- сканы нескольких интерфейсов раздельно;
- D-010 и уточнение D-005 записаны, HANDOFF обновлён.

## Сделано

- **Сетевые события за 7 дней** — счётчики по журналу, провайдеру, ID и уровню, с первым и последним временем и списком времён (до 200, новые первыми) для графика разрывов.
  - **System:** провайдеры сетевых компонентов Windows (Tcpip, NDIS, DHCP, DNS-клиент, WLAN, NLA, RAS, WinDivert и др.) и драйверы физических адаптеров по имени файла драйвера (`Netwtw14`, `rt68cx21x64`, …).
  - **Operational-журналы:** WLAN-AutoConfig, NetworkProfile (только 10000/10001 — подключение и отключение), NCSI (4042 — доступность интернета), DHCP/DHCPv6 Admin.
- **Отбор XPath-запросом на стороне журнала.** Весь System за неделю на машине разработки — ~31 000 событий и 8,7 с, из них 28 000 — CProCtrl и коммутатор Hyper-V. Выборка — ~1 000 событий и ~2,5 с. Неизвестный провайдер в XPath не роняет запрос (проверено тестом); недопустимые символы в имени провайдера отбрасываются.
- **`logs[]`:** какие журналы читались, существуют ли, включены ли.
- **На машине разработки:** `ok`, ~2,5 с, 37 КБ; 977 событий в 47 группах; снимок из 11 модулей ~34 с.
  - NCSI 4042 — 104 раза: смена доступности интернета;
  - NetworkProfile — 91 подключение и 44 отключения;
  - драйвер Wi-Fi `Netwtw14` — серии событий 7005/7010/7017/7027/7029/7036 по 22 раза;
  - WLAN — 22 отключения в System (10001) и 19 предупреждений 10002;
  - Tcpip 4207 — 18 ошибок;
  - WinDivert — 33 события.

## Отклонения от TZ.md

1. **Сообщения событий не собираются.** ТЗ: «ошибки адаптеров, DNS-клиента, разрывы линка за 7 дней» — формы не задаёт. Текст и данные событий содержат имена хостов, адреса, SSID, имена пользователей; хранятся только счётчики и время. Объяснение события — по каталогу ID в анализаторе (этап 2).
2. **Шире «ошибок».** Берутся все уровни, не только ошибки: разрывы линка у драйверов и подключения/отключения сети пишутся как Information. Также взяты WLAN-AutoConfig, NCSI, NetworkProfile, DHCP — без них «разрывы» не видны.
3. **DNS-Client/Operational не читается.** Это журнал запросов (история посещений), по умолчанию выключен. Ошибки DNS-клиента берутся из System (`Microsoft-Windows-DNS-Client`, таймауты 1014).

## Кандидаты в DECISIONS.md

1. **D-011 (предлагается). Журналы событий: только счётчики и время.**
   - Сообщения и данные событий не собираются.
   - Список времён — до 200 на группу.
   - DNS-Client/Operational не читается.
   - Смысл ID — каталог анализатора, в JSON (этап 2).
2. **Список источников событий — в коде модуля** (`$SystemProviders`, `$OperationalLogs`), а не в JSON, как сигнатуры VPN. Обоснование: источник меняется вместе с кодом разбора (фильтр ID у NetworkProfile). Каталог значений событий для анализатора — отдельно, в JSON правил. Если нужно править список без кода — вынести в `collectors/events-sources.json`.

## Открытые вопросы ревьюеру

1. **Период 7 дней жёстко задан** (ТЗ). Нужен ли параметр для расширенного режима (например, 30 дней)? Сейчас на машине разработки 7 дней — ~1 000 событий, 30 дней будут ~4 000 и дольше. Решает владелец.
2. **CProCtrl — 16 000 событий в неделю** (ID 292). Если это компонент СКЗИ, а не сетевой, модуль его не трогает; но такой поток событий сам по себе может быть находкой («служба спамит журнал»). Вне рамок `events`, вопрос — нужен ли общий счётчик «самые шумные провайдеры System» (без сообщений, только имя и число)? Дёшево: одна агрегирующая выборка ~9 с — заметно для снимка. Решает владелец.
3. **Каталог ID для разрывов линка** у драйверов зависит от производителя (Intel `Netwtw*`, Realtek `rt*`, Intel проводные `e1*`). Собирать его — задача этапа 2; на стенде стоит записать события вживую, выдернув кабель и отключив Wi-Fi.
4. **Не проверено вживую:** Windows 10; машина без журналов WLAN; журнал, выключенный политикой (`enabled = false`). Покрыто логикой `logs[]`, без фикстур.
