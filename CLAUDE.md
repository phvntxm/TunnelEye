# TunnelEye — инструкции для Claude Code

## Проект

Инструмент диагностики сети Windows-ПК в один клик. Полное ТЗ — `docs/TZ.md`. Это источник истины: перед любой задачей сверяйся с ним; если задача противоречит ТЗ — остановись и спроси.

- Продукт: **TunnelEye**. Ядро анализа: **Argus** (`Argus.Core`).
- Лицензия: Apache 2.0. В каждый новый файл исходников — короткий заголовок лицензии.

## Стек

- Сбор: PowerShell 5.1 (ничего не ставить, только встроенные командлеты и утилиты Windows).
- Захват: `pktmon` по умолчанию, `dumpcap` — только если уже установлен. Npcap не устанавливать и не распространять.
- Ядро, анализатор, GUI: C#, .NET Framework 4.8, WPF. Графики — OxyPlot.
- Правила детекта: JSON-файлы, без изменения кода.
- Локализация: .resx, RU и EN с первого дня — никаких строк интерфейса в коде.
- Дистрибутив ≤ 20 МБ. Новые зависимости — только после согласования.

## Структура

```
docs/            ТЗ и журнал решений (DECISIONS.md)
collectors/      PowerShell-модули сбора, по одному файлу на модуль
src/             решение .NET: Argus.Core, TunnelEye.App (WPF), TunnelEye.Cli
rules/           JSON-правила детекта
tests/           юнит-тесты и тестовые снимки (fixtures) с известными проблемами
```

## Правила работы

1. Работаем строго по этапам из ТЗ. Текущий этап: **1 — модули сбора**.
2. Модуль сбора: независимый, вывод в JSON по общей схеме (`module`, `version`, `status`, `errors`, `data`). Падение модуля не ломает остальные. Без прав админа — частичный результат с пометкой.
3. Цикл на каждый модуль: код → запуск → проверка JSON → тест → коммит. Один модуль — один коммит.
4. Сбор **только читает** систему. Любые изменения системы — только в модуле исправлений (этап 4), с бэкапом и откатом.
5. Никаких сетевых запросов наружу из кода. Исключение — внешние тесты связи, только по явному согласию пользователя (D-002).
6. В JSON и логи не попадают пароли, ключи Wi-Fi, содержимое пакетов.
7. Решения, меняющие архитектуру или ТЗ, — сначала спросить, потом записать в `docs/DECISIONS.md`.
8. В конце этапа — сводка: что сделано, что проверено, что осталось, по критериям приёмки из ТЗ.

## Тестовый стенд

Ломать сеть (VPN, мосты, прокси, маршруты) — только на виртуалке, не на основном ПК.

## Ревью
- После завершения модуля создай .local/review/NNN-<module>.md (нумерация с 001, wifi = 001):
  сделано; отклонения от TZ.md; кандидаты в DECISIONS.md;
  итог тестов (не-админ); открытые вопросы ревьюеру.
- Перед следующим модулем прочитай .local/review/NNN-*.reply.md, если он есть,
  и выполни правки. Пункты «решает владелец» не трогай без его ответа.
- Админ-тесты владелец запускает сам; результат — .local/test-results.xml (не коммитится).
- Файлы ревью и сведения о машине разработки в git не попадают (.local/ в .gitignore).
